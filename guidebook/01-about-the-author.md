# About the Author

I've been building things on screens for thirty years. My first computer was an Apple II+ with a 300-baud modem. I was twelve, and what hooked me wasn't the technology — it was that I could make things appear out of nothing. Procedural line drawings in BASIC. I called it "looping." I'd write a few lines of code and watch the screen fill with patterns I hadn't fully imagined. That feeling — describing something and watching it come to life — has been the through-line of my entire career.

I studied computer science and started as an engineer, but I never stayed on one side of the line. I'd code something, then redesign it, then rethink the product. I gravitated toward roles where I could do all three at once — what the industry eventually started calling "creative technology." At Odopod, I helped grow the agency from four people to fifty, building award-winning work for Nike and Red Bull where I was writing code in the morning and presenting design concepts in the afternoon. At Obscura Digital, we built the largest multi-touch display in the world for Hard Rock Cafe — inventing both the hardware and the software because nothing existed that could do what we imagined. We designed what eventually became the Las Vegas Sphere, a decade before it was built.

I've also been a founder three times. At Formation, we built an AI-powered loyalty platform that delivered over a billion dollars in incremental value to Starbucks alone — raised $30 million, grew to 140 people, got acquired by BCG. At Joinable, we tried to solve the loneliness epidemic by building tools for in-person connection. Currently, I lead R&D and new product incubation at Bumble, where we're exploring how AI can help people meet, connect, and find love — responsibly.

The point isn't the résumé. The point is that I've spent my career living in the space between "what if we built this?" and "how would we actually build it?" — and for most of that time, both halves required me. The imagining and the making. The design and the code.

What's changed is that the making part has a partner now.

My path to AI-assisted building wasn't a revelation. It was a slow migration. Stack Overflow was my first real crutch — search for a problem, find a solution, adapt it. GitHub Copilot felt like autocomplete that occasionally read my mind. ChatGPT was useful for explanations but couldn't touch my actual files. Cursor wrapped AI into the editor, and that's where things started to accelerate — I could describe what I wanted and watch code appear in context.

But Claude Code was the step change.

Not because it's smarter (though it is). Because it's a *collaborator* in the fullest sense. It lives in my terminal. It reads my project files. It understands the context of what I'm building. It writes code, runs it, sees the errors, fixes them, and moves on — all in a continuous conversation. And with Opus 4.6, something shifted. The gap between "AI gets it 90% right" and "AI gets it 99% right" sounds small, but it isn't. That last 10% was where my developer brain used to kick in — catching an edge case, knowing that a particular approach wouldn't scale, remembering a security gotcha. Opus 4.6 catches those things itself. For the first time, I found myself building things where I genuinely didn't write or modify a single line of code.

I built an iOS app over a weekend. Not a tutorial project — a real app. Every feature generated by Claude. Every bug diagnosed and fixed by Claude. Every App Store configuration guided by Claude. I never opened the code in an editor to make a manual change. That had never happened before in my career.

One more piece of context: I spent four years building on Vercel. It's an excellent platform, and I have real respect for what they've built. But when I moved to Cloudflare — Workers, R2, D1, AI, DNS, all under one account — it felt like a weight lifted. Less ceremony. Less configuration glue. More direct. The whole stack is integrated in a way that makes AI-assisted development dramatically smoother, because there are fewer seams for things to go wrong.

This article comes from that experience. Not from a weekend experiment or a thought exercise — from months of building and shipping real prototypes, weekly, at a company where the work matters. I wrote this because the path I found is open to anyone with imagination and curiosity, and almost nobody knows it exists yet.
